# 后训练实验综合分析与优化建议（2026-09-22）

> 状态：当前实验决策摘要。
>
> 范围：只基于本地文档、逐篇汇总和训练/评测脚本分析；本轮未访问服务器上的训练数据、权重和原始评测目录。因此，本文给出的是证据分级后的判断和下一轮实验设计，不是对服务器产物的重新验算。

## 结论先行

1. **当前最重要的问题是混合配方对多页表格行为的破坏，不是“训练步数越多越差”。** 在同样达到 1623 步时，PMC 续训路线 `cont1623` 的 TEDS 为 0.5089、多页 `<table>` 发射 147 个；混合路线 `mix1623` 的 TEDS 为 0.3908、多页 `<table>` 发射 53 个。`mix1450 → mix1623` 还出现了回升，因此“最后 173 步造成损伤”也不成立。

2. **混合路线仍然有真实收益，不能简单删除 READoc 或单页数据。** 在剔除两轮失效文档后的公共健康集上，混合路线的 text 表现最好；健康多页文档的 per-doc Overall 也比第一轮略高。当前问题是能力发生了分化：局部文本能力变好，但长程、多页、表格结构的输出不稳定。

3. **复读是主要的灾难性失败模式，但解码旁路只能止损，不能修复识别质量。** 复读/塌缩集中在少数文档，且多个 case 从第 0 个 token 就偏离参考答案。旁路抑制可以减少数万 token 垃圾和推理时间，却把部分过生成变成塌缩，分数基本不变；根因仍应在训练配方、生成结构和模型上下文能力上处理。

4. **目前不能把责任继续归因到某一个混合源。** 现有对照区分了“PMC 同域续训”和“PMC+页拆+READoc 混合”，但混合实验还同时改变了初始化方式、数据遍历方式和样本分布；因此可以定罪“混合配方整体”，不能单独定罪 READoc 或页拆集。

5. **下一步应先做受控配方消融并固定行为指标。** 在继续扩大训练前，必须把表格覆盖、漏表、标题块减少和复读纳入验收；只看官方 Overall/TEDS 会掩盖“没有输出表格”的损伤。

## 1. 证据总览

### 1.1 六条路线的核心读数

| 路线 | 数据/训练关系 | 步数 | Overall | TEDS | text | order | title87 | 多页 `<table>` | 四规则失效 |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|
| base | 未训练 | 0 | 0.7554 | 0.5547 | 0.7995 | 0.9351 | 0.6862 | 142 | 6 |
| full-ce | READoc | 213 | 0.7400 | 0.5248 | 0.7918 | 0.9278 | 0.6668 | 114 | 8 |
| pmc16k | PMC，首次训练 | 1160 | 0.7092 | 0.4686 | 0.7658 | 0.9065 | 0.6697 | 130 | 11 |
| mix1450 | PMC+spage+READoc | 1450 | 0.6564 | 0.3665 | 0.7425 | 0.8720 | 0.6210 | 38 | 17 |
| mix1623 | PMC+spage+READoc | 1623 | 0.6709 | 0.3908 | 0.7527 | 0.8879 | 0.6150 | 53 | 12 |
| cont1623 | PMC，`pmc16k` 续训 | 1623 | **0.7205** | **0.5089** | 0.7610 | 0.9060 | 0.6777 | **147** | 9 |

读表时需同时注意三点：

- base/full-ce 的历史推理 `max_length` 是 20480，新路线是 32768，失效篇数不能直接按绝对数量横比。
- TEDS 是按可匹配表格池加权；没有输出的 GT 表格不会自动记 0，而是从分母消失。
- `cont1623` 不是完美的单变量实验：它从 checkpoint-1160 续训，使用第二遍数据，并按 1623 步重铺 cosine 学习率。

### 1.2 最关键的对照

`pmc16k → cont1623`：数据域保持 PMC，额外训练 463 步。TEDS 从 0.4686 上升到 0.5089，多页表格发射从 130 上升到 147，失效篇从 11 变成 9。

`pmc16k → mix1623`：训练步数相同为 1623，但混入 2000 条页拆单页和 1706 条 READoc，并从头训练。TEDS 降到 0.3908，多页表格发射降到 53。

`mix1450 → mix1623`：同一混合配方后 173 步，Overall 由 0.6564 回升至 0.6709，失效篇由 17 变成 12，多页表格发射由 38 变成 53。这说明损伤不是在最后 173 步一次性引入的，也不能用“训练到某个尾段必然塌缩”解释。

这三格足以支持“配方差异是主要嫌疑”，但还不足以回答“READoc 还是 spage 负责”。

## 2. 原因分析

### 2.1 已基本确认：混合配方改变了 merge 路径的结构信号

第二轮混合数据的构成有两个明显变化：

- PMC 全文行含表比例约为 63.6%，混合后全体目标字符中的 PMC 占比下降，merge 路径含表行比例约降至 52%–56%。
- `build_pmc_singlepage_jsonl.py` 明确跳过包含 table block 的页。因此新增的 spage 样本不会给单页路径补充表格监督，反而增加了单页/短目标的权重。

这能解释“单页 `<table>` 发射基本不变、多页 `<table>` 大幅下降”的方向，但不能单独解释下降幅度。表格信号的稀释更像是触发因素或放大因素，而不是完整机制。

一个实际的配方问题是“1.4 倍过采样”容易被误读：如果 1.4 倍只是把 PMC 含表行整体重复 1.4 次，按当前 52%–56% 的含表基线，含表占比只会升到约 60%–64%，达不到建议中的 75%。若目标真是 75%，相对于非含表行需要约 2.4–2.8 倍的含表权重；最终仍应以实际行级统计，而不是倍数名称验收。

### 2.2 高可信但未完全证明：R-SWA 窗口放大了复读

审计记录给出了一条相当一致的证据链：

- 未训练 base 在同类解码下也会复读，说明这不是训练数据直接教出来的模式。
- 6 个重点 case 中多数从第 0 个 token 就偏离参考答案；偏离前的 128-token 窗口没有明显重复，重复是偏离之后形成的结果。
- 官方模型训练和推理都使用 128-token 的答案侧滑动窗口；一旦周期性输出形成，更早的答案会被环形缓存覆盖。
- 项目已有的 n-gram 处理器只禁止窗口内的精确 n-gram，数字递增、近似重复和窗口外重复仍可继续。

这支持“架构固有倾向 + 解码放大”的工作假说，但还不是 attention 级别的直接因果证明。若要坐实，需要在服务器上做窗口/解码对照，并保证训练和推理的窗口设置一致。

### 2.3 已排除或暂不支持的解释

现有审计没有发现以下问题是主因：

- 训练数据截断、样本丢弃、EOS 缺失或不同 PDF target 拼接；
- packing、batch 拼接、label mask 或 LoRA target 挂载错误；
- 循环文本直接存在于训练集，或 GT 自身存在段落级复制；
- “只要继续训练就必然变差”的单调步数规律。

这不代表数据质量绝对没有问题，而是说明下一轮不应再优先花时间寻找已被审计排除的 EOS/拼接类 bug。

### 2.4 被现有检测规则漏掉的失败

四条规则（重复率、长度过长、长度塌缩、zlib 压缩比）抓不到“长度正常但结构少了”的文档。典型例子是 38 页的 `4-2段落中带「图x-x」`：混合路线标题块从 85 降到 27，表格质量明显下降，但输出长度仍处于正常范围。

因此目前至少有三种不同风险，不能用一个“失效篇数”概括：

1. 复读/过生成：输出极长，直接污染表格和顺序分数。
2. 塌缩/早停：输出过短或只保留局部结构。
3. 结构性减配：长度正常，但标题、表格或跨页连接缺失。

第三类是当前评测闭环最大的盲区。

## 3. 评分和验收需要先修正的地方

### 3.1 同时报告“发射”和“得分”

每个新路线至少要落账：

- 全库和多页/单页的 `<table>` 发射数；
- GT 表格数、可匹配 pred 表格数、零计分表文档数；
- 每篇标题块数与 GT 标题/章节数量的比值；
- 四规则失效名单及其形态，而不只是总数；
- 官方 TEDS，以及将未输出 GT 表记为 0 的补充 TEDS。

官方分数继续保留，补充指标用于防止“少输出导致分母消失”被误读为质量提升。

### 3.2 统一统计范围和协议

后续对照必须固定：相同的 `max_length`、prompt 路由、dpi、ngram 参数、剥壳规则、129 篇输入和 title87 重建口径。报告中“194→149”与“262→215”分别对应不同统计范围，不能都写成全库计分表数。

### 3.3 建议的行为验收门

在现有门槛基础上增加以下硬指标：

- 严格复读/塌缩不超过 3 篇，zlib 型长循环为 0；
- 多页 `<table>` 发射至少达到 PMC 基线的 85%（约 110 个），并报告覆盖率；
- 健康集 text 不低于混合路线，避免以修表格为代价丢掉文本收益；
- 结构性监控中，关键长文档的标题块和 GT 表格覆盖率不能显著下降；
- 训练 loss 只能作为诊断信息，不能作为通过条件。当前 PMC 续训的 loss 很低，但行为指标仍决定是否可部署。

## 4. 后续实验优先级

### P0：建立真正可比的配方消融

从同一 Base、同一 LoRA 配置、同一总步数和同一学习率调度启动，至少做四条臂：

| 臂 | 数据 | 目的 |
|---|---|---|
| A | PMC 全文 | 复现 merge/表格强基线 |
| B | PMC + READoc | 分离 READoc 的文本收益和表格影响 |
| C | PMC + 当前 spage（不含表页） | 单独观察单页样本稀释效应 |
| D | PMC + READoc + 含表 spage v2 | 检验补回单页表格监督是否有效 |

每条臂应使用相同步数、相同验证集和相同评测协议；至少保留一个从头训练的 PMC 对照，不能只拿续训结果和混合结果比较。

判定逻辑：

- 只有 C/D 退化而 B 稳定：spage 构造或单页比例是主因；
- B/C/D 都退化而 A 稳定：混合带来的分布冲突或训练调度是主因；
- A 也在相同协议下退化：应转向架构窗口、解码和长程生成机制；
- 表格发射恢复但 text 明显下降：采样权重过高，需要按 prompt/页数/表格密度做分层采样，而不是盲目复制行。

### P1：修正数据配方，而不是删除有效数据

建议保留 READoc，先做以下低风险调整：

1. spage v2 纳入经人工抽验的完整表格页；跨页表格被截断的页仍排除。
2. 以“训练行形态”分层计数：单页/多页、含表/不含表、页数桶、目标长度桶，而不是只看总行数。
3. 用采样权重把 merge 含表比例拉到一个可验证的目标（例如 70%–75%），并把实际比例写进 recipe audit。
4. 对 benchmark 中的统计图、扫描、双栏和跨页断表保留少量 hard-case 监督，但避免让 129 篇评测集直接泄漏到训练目标。

### P2：把解码旁路定位为止损组件

重复检测可以继续保留为实验旁路或线上 watchdog，目标是限制垃圾输出和推理耗时，而不是宣称提升 OCR 质量。下一版应重点修正两点：

- 对数字归一、HTML 表格行签名和近似重复分别做误触发测试；
- 触发后记录原因、token 位置和截断状态，不能把被强制 EOS 的结果直接当作正常预测。

在没有证明有效前，不建议用 aggressive 截断结果替换历史主协议分数。若要尝试长度上限，应使用基于页数/视觉 token 和生成分布的上限，并单独报告截断率。

### P3：若配方消融仍失败，再做架构/上下文实验

如果 PMC-only 在统一协议下也持续出现长文档结构性减配，下一步才值得投入 R-SWA 窗口扩展或分段生成实验。训练和推理窗口必须同时改变，并增加长文档的跨页一致性评测；仅修改推理窗口可能造成新的 train/inference mismatch。

## 5. 最终判断与信心等级

| 判断 | 信心 | 依据 |
|---|---|---|
| 混合路线存在真实的多页表格退化 | 高 | cont1623/mix1623 同步数对照，多页表格发射和 TEDS 同向差异 |
| 退化不是简单由“步数更多”造成 | 高 | 同配方 1450→1623 回升；同 PMC 续训 1160→1623 回升 |
| 表格信号稀释参与了退化 | 中高 | 数据构成和单页 builder 明确支持，但尚未有源级消融 |
| READoc 单独是罪魁祸首 | 低 | 目前没有 READoc-only 对照 |
| spage 不含表页是重要因素 | 中 | 代码事实明确，因果影响仍需含表 spage v2 对照 |
| 128-token 窗口放大复读 | 中高 | base 复读、case 首偏离、训练/推理窗口一致；缺少窗口消融 |
| 解码旁路能提升最终 OCR 质量 | 低 | 现有 bypass 分数几乎不变，且有误触发 |

**当前推荐路线**：先做统一步数的 A/B/C/D 配方消融，保留 READoc，补齐含表单页样本，同时把表格覆盖率和结构性减配纳入验收；在此之前不建议继续扩大训练规模或把 bypass 结果作为主模型质量改进。
