# Unlimited-OCR 后训练周报:两轮 Full-CE 训练的评测结果与失效分析

日期:2026-09-20(Asia/Shanghai)
范围:2026-08-30 至 2026-09-20 周期。本报告是对 2026-09-17 周报的全局重写,整合了此后的
两轮实验独立复核与复读根因排查结论。结构按"实验设置 → 结果 → 现象与分析 → 结论"组织。
逐篇分数与完整评分产物见 §5 事实源,不在本报告列出。Title Prior 路线此前已闭环(9 套全回退、
不部署),本周期未重跑其任何评测。

## 摘要

本周期完成两轮 Full-CE 后训练并在 129 篇统一协议上评测:第一轮 `pmc-fullce-16k`
(PMC 单数据集)加权 Overall 0.7092,第二轮 `pmc-readoc-spage-16k`(PMC + 单页拆分 +
READoc 混合)0.6709,均低于未训练基座的 0.7554——数据加码、步数增加,总分反而逐轮
下降。

独立复核(全部数字从原始产物重算)表明,损失不是均匀的,而是集中在两处:**约 12 篇
文档上的解码期复读/塌缩**,和**健康文档的多页表格输出坍塌**。把这两处修好,估算可
回升约 9 个百分点,与对基座的全部差距相当。复读已查明为解码期问题:循环内容不在训练
数据里,未训练基座同样复读;主因是基座注意力的答案窗口只有 128 token——模型看不到
自己稍早写过的内容,循环一旦形成便无法自察;数据侧已基本排除。与此同时,模型确实
学会了要学的东西:Train Fit 拟合为项目历史最好,健康文档上的文本能力四路最高。

问题因此不在"没学会",而在"全文合成"类长程任务与基座架构记忆窗口的错配。下一步
最优先的验证是 `pmc-fullce-32k` 断点续跑:同数据、更多步,可把"步数"与"数据配方"
两个混杂因素分开。

## 1. 实验设置

### 1.1 数据与训练路线

PMC 数据 v2.2.1 全量定稿(18,400 篇,QC err=0;规则总账与数据对账指南见 RULES_LEDGER
_2026-09-16)。Full-CE 训练数据复刻 readoc-view-16k 范式构建:16k 集 10,292 行
(9,284 train / 505 validation / 503 test),32k 集 17,469 行(16k ⊂ 32k 同切分),页图
211,098 张 missing=0;构建期硬过滤 `273×页数 + 4 + target ≤ max_length`,实测 0 截断、
0 丢弃。

| 路线 | 训练数据 | 行数 | 步数 | 多页/单页 prompt | GT 中位字符 | 含 HTML 表格篇占比 |
|---|---|---:|---:|---|---:|---:|
| base(不训练) | — | — | — | — | — | — |
| readoc-view full-ce(0827) | READoc-1706 | 1,706 | 213 | 1,706 / 0 | 10.2k | 0% |
| pmc-fullce-16k(第一轮) | PMC | 9,284 | 1,160 | 8,911 / 373(4.0%) | 38k | 63.6% |
| pmc-readoc-spage-16k(第二轮) | PMC + 页拆单页 2,000 + READoc | 12,990 | 1,623 | 10,617 / 2,373(18.3%) | 30k | 45.4% |

中位字符为 GT(target 文本)字符数的 p50,含表占比为含 `<table>` 的行占比(每行 1 篇)。
第二轮两格由 12,990 行全量实测(30,127 / 45.4%);各分量 p50:PMC 37,971 / 页拆单页
4,158 / READoc 10,176。

页拆单页集(spage):从 32k−16k 差集(7,177 篇,与 16k 零重叠)拆出的单页样本 2,000 行,
全部为 `document parsing.` prompt,0 含表(构建时跳过了表格页)。多页数据统一用
`Multi page merge.` prompt(官方推理默认 `Multi page parsing.`,base 评测仍走官方)。

训练配置三路一致:LoRA r16 / α32 / dropout 0.05 / lr 2e-5 cosine / 1 epoch / 全局 batch 8;
`full_ce` 原生交叉熵;LoRA 挂载 84 个模块(attn + dense-MLP + shared-experts,routed
experts 冻结);max_length 16k 配方 16,384、32k 配方 32,768。0827 基线推理 max_length
为 20,480,两轮新模型为 32,768——**跨轮比较失效文档数必须带上这一差异**。

### 1.2 评测协议

129 篇统一协议(PDF→Markdown),与 0827 基线口径对齐;推理按页数路由 prompt(单页
109 篇走 `document parsing.`、多页 20 篇走 `Multi page merge.`),greedy 解码。评分输入为
剥壳后的 pred_clean(grounding 协议壳文字必须剥除,否则污染文本分;本模型 129/129 零
协议 token 残留)。两套指标:

- **OmniDocBench Total**(公式项计入其中):TextEdit / TEDS / FormulaEdit 分量。TextEdit
  与 FormulaEdit 为编辑距离(越低越好),TEDS 为相似度(越高越好)。
- **AgentBuilder 加权 Overall = 0.3·text_acc + 0.3·TEDS + 0.3·order_acc + 0.1·title**。
  text/order 为文档加权,TEDS 按表格加权。title 分量为 87 篇有 GT 标题文档上的标题分
  (标题 level 0.3 / 内容 0.7),经标题重建管线修复后四路同口径重测(原口径只认剥壳文本的
  ATX 标题,grounding 协议下标题在壳内、剥壳即灭,四路结构性塌零;修复只影响 title 分量
  与 Overall,Total 不受影响)。

评分覆盖 128/129:`5-1双栏表格2` 因模型输出 92% 重复行导致表格 matching 不收敛,不计入
聚合(第一轮 Total 缺口有界 ±0.2)。

### 1.3 失效文档检测规则

后续分析中"失效文档"按以下四条检测规则从输出侧自动判定(对全部 129 篇、四条路线统一
执行):① 行重复率 ≥0.3;② 输出长度 ≥2× 参考答案长度;③ 塌缩(输出 ≤1/3 参考答案
长度);④ zlib 压缩比 <0.15(抓单行超长循环,行间重复率检不出)。①②④ 判"复读",
③ 判"塌缩"。规则覆盖不了的第三类失效见 §3.3。

## 3. 现象与分析

### 3.1 现象一:复读——解码期病理,掉分的主要直接原因

**现象**。少数文档上输出出现复读:同一行、同一块或同一数列无限重复。按 §1.3 检测规则:
严格复读文档 base 3 篇 / readoc-view full-ce 2 篇 / 第一轮 9 篇(另塌缩 2 篇)/ 第二轮
9 篇(另塌缩 3 篇)。两轮名单轮换:第一轮 9 篇中 6 篇第二轮修复,第二轮新增 6 篇,3 篇
两轮共有。复读文档单篇 Overall 损失最大达 −0.80(珠海机场_工作证管理细则_6)。典型
例子:该篇参考答案仅 445 字符,模型输出 28,502 token。

**循环的四种形态**(输出原文片段):

形态 1|页脚电话循环,末位数字阶梯递变(珠海机场_工作证管理细则_6,第二轮):

```text
TEL: 0755-822-8228
TEL: 0755-822-8228
TEL: 0755-822-8228
TEL: 0755-822-8229
……
TEL: 0755-822-8240
```

形态 2|标题计数递增(2-1横向合并,第一轮;重复单元 11,074 字符):

```text
### 210、分部信息
### 211、分部信息
### 212、分部信息
……
```

形态 3|数列递增(4-1统计图2,第二轮;中车株洲_方案技术_6,第一轮,单行 3.2 万字符):

```text
99. 100. 101. 102. 103. 104. 105. 106. 107. 108. ……
```

形态 4|表格空行循环(中车株洲_方案技术_16,第二轮;重复单元仅 115 字符):

```html
</td><td colspan="2"></td></tr><tr><td>输出频率 129</td><td colspan="2"></td></tr><tr><td>输入电流 129</td>……(循环)
```

另有域漂移形态:珠海机场_工作证管理细则_6 的最长重复单元(14,942 字符)是上市公司股东
大会公告套话,与输入文档(机房工作证细则)和训练数据均无关——低信息量页面上模型漂移到
高频模板文体并循环。

**三条"非数据"证据**:

1. 把每篇的最长重复单元在 pmc-fullce-16k / pmc-spage-16k / readoc-view-16k 三套训练数据
   中检索,**全部 0 命中**。
2. 参考答案侧无对应自重复:失效文档 GT 的行重复率 0.01-0.11,全部训练数据按字符量加权的
   行重复率 ≤0.12%(8-gram 高重复全部来自表格行、署名等短行的自然复现)——GT 侧不存在
   "训练数据教模型复读段落"的证据。
3. **未训练 base 同样复读**:同解码配置下重复行 ≥10% 的文档 base 有 9/129;严格复读
   3 篇。复读不是训练新引入的行为,训练后篇数上升(base 3 篇、0827 full-ce 2 篇 → 两轮
   各 9 篇)。

**起步即偏:复读的时序结构**。对 6 个复读 case 做首偏离解剖(输出与参考答案的 token 级
对齐):5/6 篇从**第 0 个 token 起即偏离参考答案**(k_eff=0),唯一中段偏离恰发生在参考
答案进入表格的位置;**偏离前 128-token 窗口内 8-gram 重复 5 篇为 0、1 篇为 2**——重复
模式是偏离的结果,不是前兆。即:模型先在低信息量/特殊版式首页(工作证页脚、统计图横轴、
标准封面、表格框架)上漂移到高频模板内容,随后进入循环;而不是"写到一半掉进循环"。

**机理与原因排序**(可能性从高到低):

1. **主因:基座滑动窗口注意力(R-SWA)答案窗口自循环(架构固有)**。训练注意力掩码与
   推理环形缓冲区的答案窗口均为 128 token(config `sliding_window_size=128`,官方设计,
   本项目未改动):前缀(全部页图 + prompt)全可见,答案侧只看最近 128 个已生成 token。
   一旦进入周期 ≪128 的循环,更早的已写内容被环形覆盖,模型无法"看到自己已写过";训练
   期窗口同为 128,模型从未学过回看更远的历史输出。
2. **放大因子:解码侧无有效防重**。官方推理默认无任何防重(`no_repeat_ngram_size=0`);
   项目自加的滑动窗口 ngram 处理器(35, 窗口 128/1024)只禁"最近窗口内出现过的精确
   n-gram"的延续:周期循环的唯一续写被禁后,greedy 取次优 token,循环以变异形态继续
   (观测到 8228→8229→8230、210→211→212 恰为此机制产物);窗口外的重复完全不设防,
   而实测循环单元跨度 115 字符 ~ 32k 字符。
3. **放大因子:训练量,与数据配方混淆未分离**。LoRA 超参与 0827 full-ce 参考完全一致、
   routed experts 冻结、1 epoch、无 loss 崩坏形态;但自 0827 起严格复读篇数随步数上升:
   0827 full-ce(213 步)2 篇 → 第一轮(1,160 步)9 篇 → 第二轮(1,623 步)9 篇
   (base 0 步即有 3 篇;且 base/fc 推理 max_length 较小,检出率被压低)。是"长文档连贯
   输出任务 + 更多步数"放大固有倾向,还是数据配方问题,现有产物无法区分——
   `pmc-fullce-32k` 断点续跑(checkpoint-400 就绪)是现成的分离实验。
4. **已排除项**:数据/截断/EOS(0 截断、0 丢弃、每样本恰 1 个 EOS、训练数据 sha 全量
   对账 0 不一致)、packing/拼接(packing=false、bs=1)、page boundary 丢失(词表本无
   page 类 token,官方多页输入即 273 visual token/页 + 页间 1 个分隔 token,训练与评测
   一致,不存在"去掉"动作)、其他代码 bug(未发现)。复读治理的靶点在解码/生成结构侧,
   不在数据清洗。

### 3.2 现象二:健康文档的多页表格输出坍塌——第二轮的最大增量损失

**现象**。第二轮相对第一轮:多页文档的表格发射量与质量大幅下降,单页文档完全持平;
同时第二轮在健康文档上的文本能力是四路最高——收益与损失在不同部位。

| 证据 | 数值 |
|---|---|
| `<table>` 发射(全库) | base 214 / 0827 full-ce 182 / 第一轮 195(单页 65 + 多页 130)→ 第二轮 118(单页 **65 持平** + 多页 **53**) |
| 官方 pooled TEDS | 单页 0.7327→0.7343(持平);多页 0.3748→**0.2386** |
| 计分表数 | 194 → 149 |
| 逐表 TEDS 求和 | 122.5 → 84.0(−38.5);失效文档内 −24.15(63%),健康文档 −14.4(37%) |
| 健康文档中跌幅最大者 | 1-3单元格内换行1:28 张计分表共 15.34 分 → 20 张共 0.26 分 |
| `<PAGE>` 发射 | base 181 → 0827 full-ce 149(仅 213 步)→ 第一轮 137 → 第二轮 49,单调衰减;三路全部出现在多页文档,GT 0 个 |

**"表格信号稀释"解释不充分**。第二轮混入 READoc(0% 表格)与页拆单页集(0% 表格),
merge 路径含表行占比从约 62-66% 降到约 52-56%;但 `<table>` 发射降了 59%,单页发射却
完全持平——稀释幅度(约 −10pp)与行为变化(−59%)量级不成比例,且稀释无法解释单页/
多页的分化。

**步数混淆未排除**。第二轮比第一轮多训 463 步;`<PAGE>` 发射 181→149→137→49 的单调
衰减同样兼容"训练步数"解释——格式行为随训练深度系统性改变(基座输出习惯被训练目标
分布覆盖),`<table>` 发射坍塌可能是同一机制的温和表现。现有产物无法区分"数据配方"与
"训得更多",这是当前最大的归因缺口(§4)。

**两点澄清**。其一,`<PAGE>` 发射不是多页缺口的来源:base 发射最多(181 处)但多页文本
分四路最好,发射量占多页输出字符 ≤0.46%。其二,健康多页并非全面退化:剔除失效文档后
第二轮健康多页 per-doc Overall 反而 +5.9pp(0.4087→0.4676,修复了第一轮 4 篇多页失效)。

### 3.3 现象三:长文档结构性简化——检测规则的盲区

**现象**。个别长文档输出长度正常,但标题块与表格的数量/质量大幅下降——§1.3 四条检测
规则全部漏检,混在健康集里持续拖低健康集表格分。

Case:`4-2段落中带「图x-x」`(38 页,未被任何规则标记)

| 指标 | pmc-fullce-16k(第一轮) | pmc-readoc-spage-16k(第二轮) |
|---|---:|---:|
| 标题块数 | 85 | **27** |
| 计分表数 × 表均 TEDS | 42 × 0.421 | 35 × **0.181** |
| text_acc | 0.279 | **0.134** |
| 输出长度比 | 正常(未触规则) | 正常(未触规则) |

同型:`1-3单元格内换行1`(35 页)28 张计分表 15.34 分 → 20 张 0.26 分。全局上,标题块
总数 502→345 的构成:失效文档内 −90、本 case 单篇 −58、其余全部文档合计仅 −9——**标题
回退集中在个例,不是面上现象**。此类"悄悄减配"既不触检测规则,也不表现为单篇总分崩塌
(被 text/order 项部分掩盖),是健康多页 TEDS 下降的主力之一。

### 3.4 现象四:评分口径缺口——未输出的表格不计 0

**现象**。官方 TEDS 评分池由可匹配的 pred 表格构成:模型未输出的 GT 表格不是计 0 分,
而是从分母消失;单篇缺 TEDS 项时按剩余权重重新归一。两个机制都不直接惩罚"不输出"。

- `4-1统计图2`:GT 3 张表;第一轮计分 15 张(表均 0.087),第二轮计分 **0 张**(计分文件
  为空,不是 0 分)。
- 重归一验算(第二轮该篇):0.3×0.0277 + 0.3×0.0606 + 0.1×0 = 0.0265,而该篇 per-doc
  Overall 0.0378 = 0.0265/0.7。
- 零计分表文档数:第一轮 66 / 第二轮 66(发生率未涨,构成轮换)。

**影响**。TEDS 0.3908 对"不输出表格"偏乐观,真实表格损伤被低估(部分损伤转移到
text/order 项,如同篇 text_acc 0.028)。**任何跨路线 TEDS 对比必须同时报告计分表数与
零计分表文档数**,否则无法区分"表格变差"与"表格变少"。此口径只影响解读,已发布分数
不追溯修改。

### 3.5 页数拆分归因:缺口在多页,不在单页

129 篇 = 单页 109 + 多页 20。按页数拆分的 per-doc Overall:

| 页数 | base | pmc-fullce-16k(第一轮) | pmc-readoc-spage-16k(第二轮) |
|---|---:|---:|---:|
| 单页(109 篇) | 0.7742 | **0.7757** | 0.7618 |
| 多页(20 篇) | 0.5745 | 0.4004 | 0.3908 |

- **第一轮对基座的缺口几乎全在多页**:单页 0.7742 vs 0.7757 打平(第一轮训练数据中单页
  prompt 仅 4%),纯 PMC merge 训练未伤单页;多页 0.5745 → 0.4004。
- **第二轮的额外伤害约 85% 落在单页**(文档加权),但其中失效文档占大头:健康单页
  (剔失效,n=104)仅 −0.95pp(17 升/13 降),净伤害集中在 5-6 篇——4 篇短文档行内
  循环新病(全在 `document parsing.` 路径)、1 篇中段内容缺失约 700 字符(四条检测规则
  均不触,per-doc 0.707→0)、1 篇少发 1 张表。对应训练覆盖:单页 prompt 占比 0%(base
  配方)→ 4.0%(第一轮)→ 18.3%(第二轮,页拆集引入)。
- **健康多页(剔失效,n=15)第二轮反而 +5.9pp**。

### 3.6 统一解释、结论与局限

**损失是结构性的、可定位的,不是整体退化。** 三条证据链:①第一轮在剔除失效文档后反超
两个对照(§2.3-b);②第二轮的增量损失 76% 来自 12 篇失效文档(§2.3),其余几乎全在
健康文档的多页表格(§3.2);③域内拟合与局部能力真实提升——Train Fit 项目历史最好
(§2.2)、健康文档 text 四路最高、健康单页无损、健康多页反而改善。两处损伤的治理回升
估算(≈+4.8pp 与 ≈+4.4pp)合计 ≈+9pp,与第二轮对基座的总差距(−8.4pp)同量级。

**统一解释(与全部观测相容的工作假说,非已证机制)。** "Multi page merge"任务要的是
全文级长程结构化输出:跨页表格要记得开过哪些表、全局标题层级要记得全文结构、长输出不
循环要记得写过什么。基座 R-SWA 架构的答案侧记忆只有 128 token(官方设计,原任务形态
是逐页流式转录):窗口之内的局部、短程、逐段转写能力训练后变强;窗口之外的长程能力
做不到,于是塌——复读是最剧烈的表现(直接死循环),多页表格不发射与标题简化是温和
表现(悄悄少干)。"越训越差"的原因:训练每推一步模型向训练目标分布靠近,超出架构可
实现范围的部分就多塌一点;`<PAGE>`/`<table>` 发射随步数单调改变是该机制在格式层的可见
信号。此解释有架构事实与旁证链支撑,但缺 attention 级直接消融取证;步数与配方的混淆
也未分离(§4-1)。

**局限**。①129 篇小样本:剔除后健康多页仅 8-15 篇,title87 ±1 篇 = ±1.1pp,健康集
差异的置信区间宽,结论以方向为主;②步数 vs 配方混淆未分离;③评分口径缺口(§3.4)
只影响解读;④Train Fit 数字引自验收报告,未独立复验(eval_loss 曲线已独立核实);
⑤0827 base/fc 的 pred_clean 存量孤儿壳残留约 231 字符(<0.01pp,方向为 baseline 略被压,
已登记不改)。
