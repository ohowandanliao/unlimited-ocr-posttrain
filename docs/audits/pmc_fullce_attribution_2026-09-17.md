## 3. 证据二：缺口集中在退化文档

**退化判据（四板斧，全部从 pred_clean 重算）**：行级重复 dup≥0.3；输出/GT 长度比 ≥2x；塌缩 ≤1/3；**zlib 压缩比 <0.15（行内循环，行级 dup 检不出）**。

- 严格退化（dup≥0.3 或 ≥2x）：pmc **8 篇**（base 6、fc 6、tw 8）——pmc 不但多，且更灾难性（dup 0.92、130x 行内循环、塌缩 0.08x）
- 加塌缩篇共 11 篇
- **集中度**：pmc−fc 逐文档 overall 缺口的 **58.2%**（严格 8 篇）~ **74%**（含塌缩 11 篇）；pmc−base 为 72.5%
- **order 缺口 ~95-100% 来自退化篇**（剔除后 pmc−fc = −0.003 ≈ 0）

## 4. 证据三（决定性）：反事实——剔除退化篇后排序反转

方法：从 per-doc sweep 产物按文档名剔除 8 篇退化篇的全部页/表样本，**双方同剔**，重算官方 pooled 分量。剔除前四路官方全量值均先逐位复现（pmc TEDS n=258=0.4686、fc n=237=0.5248、base n=246=0.5547、text/order 同理）。

| 分量 | base 全量→剔除后 | fc 全量→剔除后 | pmc 全量→剔除后 | 剔除后 pmc−fc |
|---|---|---|---|---:|
| text edit | 0.2005→0.1880 | 0.2082→0.1849 | 0.2342→0.1975 | −0.0126 |
| **TEDS** | 0.5547→**0.5002** | 0.5248→**0.4999** | 0.4686→**0.5296** | **+0.0297** |
| order edit | 0.0649→0.0645 | 0.0722→0.0633 | 0.0935→0.0644 | −0.0011 |

用剔除后分量重算 Overall（title 分量保持 87 篇修正值）：

| 路由 | 全量 Overall（修正口径） | **剔除退化篇 Overall** |
|---|---:|---:|
| base | 0.7554 | 0.7429 |
| fc | 0.7400 | 0.7422 |
| **pmc** | 0.7092 | **0.7473** |

**结论：pmc 的 Overall 缺口不是"整体更差"，而是"特定版式上灾难性失效"。健康子集上 pmc 反而是三路最好**（TEDS 反超 fc +0.030、反超 base +0.029；text 略逊 fc −0.013）。

两个补充：
- 该反事实还是**保守的**：4-3扫描1（内容被替换但长度正常）、3-3跨页表注（塌缩）都不在 8 篇剔除集里，把它们也剔掉 pmc 位置更高。
- TEDS 的两种口径都要说清：按篇等权的 per-doc 均值剔除后仍 −0.048/篇（pmc 在少表文档上有真实小残差）；但官方指标按表数加权（pooled），多表文档上 pmc 更强，所以**官方口径下 TEDS 缺口全部由退化篇贡献**。

**严格退化但不在 top-12 的（各自情况特殊）**：

- **4-3扫描2**：dup 0.37；**科欣环保_产业结构_5**：塌缩 0.23x。

### 5.2 案例说明的三类结论

1. **失效模式有四种**：行循环（1/2 号）、行内循环（中车株洲_6）、过生成（3/10 号）、塌缩（5 号），外加内容替换型（4-3扫描1）。全部是**解码期行为**，Train Fit 判定训练目标无此模式（数据未污染，此点引周报 §5，未独立复验）。
2. **fc 同样有 6 篇退化文档**（如珠海机场_三防_23 fc 塌缩 0.16x）——区别在 pmc 的退化篇更 catastrophically 且全部落在特定版式类型上。
3. **非退化的 top movers（6-12 号）单篇损失都 <0.21**，合计解释不了缺口主体——"广谱回归"在逐篇视角下只是小残差。

## 6. 机制：训练曲线与训练数据证据

### 6.1 训练曲线（`trainer_state.json` 实测）

| 指标 | pmc-fullce-16k | readoc-view full-ce |
|---|---:|---:|
| train_loss 末 10 条均值 | **0.0541** | 0.2803 |
| eval_loss 末段 | **0.0545-0.0546（s1000→1160 平台）** | 0.2585 |
| eval_token_acc | 0.9870（s950 后平台） | 0.9460 |

pmc 拟合深度是 fc 的 ~4.8 倍，且 **eval_loss 已平台**——16k 单域在 s1000 就饱和，继续同域训练只会加深漂移（这也是 32k 降级为消融的依据）。深拟合 → 模型把"PMC 学术文章的统计规律"（长度、表格风格、文体）当成先验，压掉了 base 的通用版式技能。

### 6.2 训练数据（两套 train.jsonl 实测）

| 统计 | pmc-fullce-16k | readoc-view-16k |
|---|---:|---:|
| 行数 | 9,284 | 1,706 |
| 目标文本 p10/p50/p90 字符 | 9,890 / **37,973** / 49,959 | 2,467 / 10,176 / 34,101 |
| 含 HTML 表格标签的篇 | **63.6%** | **0%** |
| ATX 标题行密度（行/篇） | 19.1 | 15.8 |
| 单页 `document parsing.` prompt | **373（4.0%）** | 0（100% Multi page merge.） |
| CJK>5% 的篇 | 7（0.1%） | 0 |

对照 129 集：**109/129 篇是单页**、GT 多为中文工程/表格文档、GT 表格 **0 个 thead/th**——训练分布与基准分布三个轴（页数、语言、表格风格）全部错位。

### 6.3 为什么退化不是"长度先验"直接导致

- 退化篇 GT 均值 **11,975 字** vs 非退化篇 **2,520 字**——退化集中在**长而复杂版式**的文档，不是短文档被拉长；
- GT<2000 字的 90 篇中，pmc 仅 1 篇过生成（fc 0 篇）；
- 正确表述：长度先验（p50 38k、p10 9.9k）让模型"只会一种输出姿势"，当遇到域外版式（统计图/扫描/双栏表）时以**复读/过生成/塌缩**的形式崩溃——先验是背景条件，版式类型是触发器。

## 8. v3 方案（待拍板；原优先级 4/5 已按你要求搁置）

### A. 退化治理（最高优先级，双轨）

**A1 数据轨：READoc + PMC 混合训练**（recipe 复用 pmc_s10，历史构成 PMC 2184 + READoc 1367 ≈ 62/38）

- 建议：PMC 9,284 ×1 + READoc 1,706 ×2~3（READoc 占 26-35%，总 ~14-15k 行），16k⊂32k 切分约束保持
- 原理（对应本文证据）：①稀释单域先验（长度 38k→混合后下拉、表格风格 63.6%→稀释）；②readoc 的浅拟合特性（train_loss 0.28）保留 base 技能——fc 能拿统计图1 的 text 0.966 不是因为 readoc 有图表，而是因为浅拟合没破坏 base 的视觉能力；③混合是对"健康子集已反超 + 退化篇崩溃"这一结构的最短修复路径

**A2 解码轨：复读抑制（不训练，先做，一天内出结论）**

- 现状 no_repeat_ngram_size=35 + window 128/1024 挡不住两类循环：行内循环（中车株洲_6，循环单元在窗口外）与大结构块循环（2-1横向合并，重复块 >35 token）
- 候选（按侵入性递增）：repetition_penalty 1.1~1.2 → 更小 ngram（8-16，会伤表格数字/公式，需实测）→ 生成中块级重复检测早停（行/块重复率>0.3 即停）
- ⚠️ 协议约束：改解码参数=改 0827 契约，**只能作为 v3 的旁路实验列**，不得回写历史分数；若采纳须全路由同改重评

**A1/A2 验证门**：
1. 退化篇数（四板斧）8-11 → **≤3**
2. 健康子集不回退：pooled TEDS ≥0.50、text ≥0.20、order ≤0.075（pmc 现剔除后 0.5296/0.1975/0.0644 为基准线）
3. 修正 Overall ≥ **0.7400**（fc 线）；推算区间 0.73-0.75（退化篇修复≈+2.1~2.5pp + 广谱残差部分收敛，标注为推算）
4. Train Fit：sim ≥0.6、line recall ≥0.4（域内拟合不能丢）
5. train_loss 末段 ≥0.10（拟合深度计，过深=又要漂）

**A2 单独验证**：只对 8-11 篇退化文档用新解码参数重推理（**新实验，非重跑既有评测**），看四板斧是否消除、text/TEDS 是否回到 fc 水平。

### B. 单页 prompt 过采样（次优先级）

- 现状 373/9284=4.0%，基准 109/129 篇单页；Train Fit 行 9176（单页）停在 base 协议未收敛
- 做法：jsonl 构建时单页样本提至 15-25%（373→~1,400-2,300；优先把多页文档**页级拆分**出自然单页样本，而不是复制）
- 验证：Train Fit 单页样本协议收敛；129 集单页子集（109 篇）Overall 对比；多页子集不回退

### C. 表格风格归一（v3 数据构建时顺手做，低预期）

- 现状：训练数据 63.6% 篇带 thead/th 风格，GT 0 个；模型输出实测仅 13 表/69 th 沾染
- 做法：清洗规则把 `<thead>/<th>` 降为 `<tr>/<td>`、剥 `<sup>/<sub>` 等（v2.2.1 已定稿，这是新规则 → 按工作约定：先全量实测触发分布 → 对比报告 → 拍板）
- 验证：触发分布报告；重建训练后输出 thead/th 计数→0；受影响 13 表 TEDS-S 增量；**整体预期 ≤+0.3pp**（低预期，勿当主杠杆）

### 打包建议

一轮 v3 数据（PMC 清洗 v2.2.2 表格规则 + 单页过采样 + READoc 混合 jsonl）+ 一次训练 + 上面一套验证门；A2 解码轨独立先行，不等训练。
